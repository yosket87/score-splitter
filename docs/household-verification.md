## 最終確認の合格条件

以下は合格条件。ローカル実装の証跡と、未実施の実環境配布確認を区別する。

| 境界 | 合格条件 |
|---|---|
| 同内容の2世帯 | 同月・同担当・同ラベル・同額の明細と同operation IDが共存し、一覧・集計・コピー・履歴で相手の値が返らない |
| 認証 | NULL/不明所属・期限切れを拒否し、任意の世帯ID入力で所属を選べない。認証前challengeだけが所属NULLを許す |
| AI実行 | Bの編集はAの診断をstaleにせず、Aの編集はstaleにする。古いrun tokenによる保存・補償解放は現在の実行を変更しない |
| 振込 | 再送の結果とsnapshotは所属内で一致し、foreign recordの訂正・取消を拒否する。途中失敗で台帳とrevisionが一緒に戻る |
| コピー | preview後の元行・繰越集合変更は全書込を拒否する。件数は実際の追加明細数で、トリガーの更新を数えない |
| 表示と再送 | A→B同月でAの状態が見えず、遅いA応答がBの画面・storageを変更しない。旧月単位のpendingをBへ再送しない |
| 移行保持 | ID・token・公開鍵・counter・金額・JSON文字列・利用回数・revisionが一致し、FK検査が0件。故意の途中失敗後も旧schema/値/triggerが揃って戻る |
| 配布 | 各段階のSHAとmigration集合が固定され、全経路完成前の版や旧Previewから切替後DBへ到達できない |
