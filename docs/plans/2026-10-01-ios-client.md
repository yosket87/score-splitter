# SwiftUIクライアント初期実装

> 2026-10-02のユーザー指示により、以下に記録した初期デモ方針は廃止。[実接続とデモ撤去](2026-10-02-ios-live-connection.md)でデモを削除し、実ログインのみへ変更する。

## 目的・制約
最新main ebaa2c2から、Webスマホ版の構成と配色に合わせたiOSクライアントを作る。既存Next.js WorkerとD1を共有し、既存Webの配置は維持する。本番配備・DB migrationは行わない。オンライン利用を前提にする。未知ユーザーの自動世帯作成・メールによる連携はしない。

## Task 1: iOS向けAPI
所有: src/lib/mobile-api/, src/app/api/v1/, tests/unit/mobile-api/, contracts/mobile-api.md。
既存のFirebase署名検証・D1所属/失効確認を再利用するBearer認証API。WebのCookie認証と混同しない。Firebase ID tokenのlogin/refresh交換、現在セッション照会、logoutを扱う。未知UIDの移行申請は既存承認手順へ接続するか明示的にWebでの初回連携を案内し、使えない成功レスポンスを返さない。リクエスト本文サイズ、固定エラー、no-store、入力検証を実装。APIは /api/v1 を起点、{data: ...} / {error: {code, message}} を共通形式にする。
月一覧、月詳細（収入・支出・繰越・サーバー計算済み精算結果）、収入/支出/繰越の作成更新削除、フラグ更新を提供する。入力金額は正の整数で既存保存規約に変換。D1の世帯認可を再利用し、クライアント指定世帯を信用しない。Webキャッシュの更新も考慮する。
TDDで認証拒否、期限切れ、失効、別世帯アクセス、異常入力、正常取得/変更を検証。Next.js同梱ドキュメントを読む。API契約を正確なJSON例と認証更新手順付きで記録する。

## Task 2: SwiftUIアプリ
所有: apps/ios/。
Task 1のAPI契約に接続するXcodeプロジェクト。iOS 17以上。Webの現在のモバイル画面（DESIGN.md、globals.css、月一覧、月詳細、追加編集、設定）に合わせる。月一覧→月詳細、精算額・夫婦別内訳、収入支出繰越、追加編集削除・フラグ切替、設定とログアウト。Firebase Apple/Google認証を使用する。設定ファイル/署名IDは利用者が設定可能にし秘密値を埋め込まない。実環境設定がなくても明示的なDEBUGデモモードでUI検証可能にする。デモと実環境を自動フォールバックさせない。必要な初回Web連携を案内する。
URLSessionとasync/await、Keychain、期限更新・401、キャンセル・画面/セッション切替後の古いレスポンス破棄、エラー/空/読み込み状態を扱う。Swiftで精算ロジックを重複実装せずサーバー結果を表示。Swiftテスト、シミュレータbuild、UIの表示検証を実施。READMEに設定と起動方法・未対応機能を記載。

## Task 3: 統合検証・レビュー
所有: docs/と必要な統合修正。
APIとSwiftモデルの一致、Web回帰のtypecheck/lint/unit、iOSビルド・テストを確認。Webスマホ表示とiOSスクリーンショットを比較。環境制約を明示する。全差分をレビューし重大問題を修正する。

## 初期版の範囲
月次確認と収支記録を初期版の完結した利用経路とする。振込記録の変更、AI診断、月コピー、CSV、パスキー管理は後続段階であり、見せかけの操作ボタンは置かない。DBと認証の既存安全性を維持する。
